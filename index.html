Khởi Đầu & Phân Biệt Git vs GitHub

Rất nhiều bạn mới làm quen với lập trình thường nhầm lẫn Git và GitHub là một thứ giống nhau. Thực chất, đây là hai công cụ hoàn toàn độc lập kết hợp với nhau tạo nên sức mạnh quản lý mã nguồn hiện đại:

Git là gì? Git là một phần mềm mã nguồn mở chạy trực tiếp trên máy tính của bạn. Nhiệm vụ chính của nó là theo dõi và ghi lại lịch sử từng dòng code thay đổi. Bạn có thể sử dụng Git hoàn toàn offline mà không cần kết nối mạng.
GitHub là gì? GitHub là một dịch vụ máy chủ đám mây trực tuyến thuộc tập đoàn Microsoft. GitHub đóng vai trò là "ngôi nhà chung" để bạn tải (push) các bản ghi lịch sử của Git từ máy tính cá nhân lên mạng, chia sẻ dự án cho cộng đồng hoặc làm việc nhóm cùng đồng nghiệp trên toàn thế giới.

Thiết lập danh tính đầu tiên

Sau khi cài đặt Git, việc đầu tiên bạn phải làm là khai báo tên và email của mình để mọi commit sau này đều gắn liền với bạn:

git config --global user.name "Nguyen Van A"
git config --global user.email "nguyenvana@example.com"

Beginners often confuse Git and GitHub as the same entity. In reality, they are two separate technologies working in synergy:

What is Git? Git is an open-source Distributed Version Control System (DVCS) running locally on your workstation. It tracks changes in source files offline without requiring an internet connection.
What is GitHub? GitHub is a cloud-based hosting platform (acquired by Microsoft) for Git repositories, enabling code collaboration, issues tracking, code reviews, and automated CI/CD workflows.

First-Time Identity Setup

After installing Git, configure your name and email address globally:

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

Vòng Đời 3 Vùng Dữ Liệu Git (3 States)

Để không bao giờ bị rối khi dùng Git, bạn chỉ cần nắm vững 3 trạng thái cốt lõi mà file code của bạn di chuyển qua lại:

  1. 1. Working Directory (Thư mục làm việc): Nơi bạn trực tiếp gõ code, tạo file mới hoặc xóa file trong VS Code. Git nhận diện các file này là Untracked hoặc Modified.
  2. 2. Staging Area (Khu vực tập kết chuẩn bị): Nơi bạn chọn lọc những thay đổi nào đã sẵn sàng để đóng gói. Dùng lệnh git add . để đưa file từ Working sang Staging.
  3. 3. Repository / Commit History (.git): Nơi các bức ảnh chụp nhanh (snapshot) được lưu vĩnh viễn vào cơ sở dữ liệu của Git sau khi bạn chạy git commit.
Tại sao lại cần Staging Area? Staging Area giống như bàn đóng gói bưu phẩm. Bạn có thể sửa 10 file khác nhau, nhưng chỉ muốn đóng gói 3 file thuộc tính năng đăng nhập vào 1 commit độc lập, 7 file còn lại để vào commit sau!

To master Git without confusion, you only need to understand the three main states that your files can reside in:

  1. 1. Working Directory: The single checkout of one version of the project on your local filesystem where you actively write code.
  2. 2. Staging Area (Index): A staging area file that stores information about what changes will go into your next commit.
  3. 3. Git Directory (Repository): Where Git stores the permanent metadata and object database for your project via snapshots.

Bộ 5 Lệnh Thần Thánh Hàng Ngày

Trong hơn 90% thời gian làm việc hàng ngày của lập trình viên chuyên nghiệp, bạn chỉ cần lặp đi lặp lại 5 câu lệnh thần thánh này:

# 1. Tải kho code từ GitHub về máy tính
git clone https://github.com/Dungautomation-dev/github-mastery-guide.git

# 2. Kiểm tra xem mình vừa chỉnh sửa những file nào
git status -s

# 3. Đưa tất cả thay đổi vào khu vực Staging Area
git add .

# 4. Lưu lại mốc lịch sử kèm lời ghi chú rõ ràng
git commit -m "feat: cap nhat giao dien moi"

# 5. Đẩy toàn bộ commit từ máy tính lên GitHub
git push origin main
Quy ước viết lời nhắn commit chuẩn (Conventional Commits):
• feat: Viết tính năng mới (ví dụ: feat: them chuc nang dang nhap)
• fix: Sửa lỗi (ví dụ: fix: sua loi khong bam duoc nut gui)
• docs: Cập nhật tài liệu (ví dụ: docs: bo sung readme tieng anh)

More than 90% of your daily version control routines will revolve around these five core commands:

# 1. Clone repository to your machine
git clone https://github.com/Dungautomation-dev/github-mastery-guide.git

# 2. Check workspace status
git status -s

# 3. Stage all modifications
git add .

# 4. Commit changes with a descriptive message
git commit -m "feat: add user authentication form"

# 5. Push commits to remote GitHub
git push origin main

Làm Chủ Nhánh (Branch) & Xử Lý Conflict

Quy tắc vàng của lập trình viên: Tuyệt đối không bao giờ code thẳng tính năng mới vào nhánh main! Nhánh main phải luôn luôn là mã nguồn ổn định nhất để xuất bản lên production.

Khi muốn làm một chức năng mới, hãy tạo một nhánh con riêng biệt:

# Tạo và nhảy ngay sang nhánh mới
git checkout -b feature/dark-mode

# Code xong, lưu lại
git add .
git commit -m "feat: hoan thanh giao dien nen toi"

# Quay lại nhánh chính và gộp code vào
git checkout main
git merge feature/dark-mode

Xung đột mã nguồn (Merge Conflict) là gì?

Xung đột xảy ra khi cả hai nhánh cùng sửa một dòng code trong cùng một file nhưng với nội dung khác nhau. Khi merge, Git sẽ dừng lại và đánh dấu các mốc như sau trong file:

<<<<<<< HEAD (Code hiện tại ở nhánh main)
const theme = "light";
=======
const theme = "dark";
>>>>>>> feature/dark-mode (Code từ nhánh đang gộp vào)

Cách giải quyết: Mở file đó trong VS Code, chọn giữ code nhánh nào (Accept Current Change hoặc Accept Incoming Change), xóa các dòng ký hiệu đánh dấu, rồi chạy git add . và git commit để hoàn tất!

Branches allow you to develop features, fix bugs, or safely experiment with new ideas without touching production code in the main branch.

Resolving Merge Conflicts

A merge conflict occurs when competing changes are made to the same lines of the same file on two different branches. Git halts the merge and injects conflict markers (<<<<<<<, =======, >>>>>>>) for manual review.

Giải Mã Bí Mật Tính Năng GitHub Projects

Khi vào trang cá nhân GitHub (ví dụ: https://github.com/Dungautomation-dev), bạn sẽ thấy tab Projects nằm ngay cạnh Repositories.

GitHub Projects là gì? GitHub Projects (Projects v2) là công cụ quản lý tiến độ công việc, lập kế hoạch phát triển và điều phối task tương tự như Trello, Jira hay Notion, nhưng được tích hợp 100% bản địa vào hệ sinh thái GitHub!

So sánh bộ 3: Repository vs Issue vs Project

Thành phần Vai trò thực tế Ví dụ đời thường
Repository Chứa code, file và thư mục thực tế Thư mục dự án trong ổ cứng
Issue Mô tả một task hoặc lỗi cần sửa Tờ giấy ghi chú dán tường (Post-it)
Projects Bảng điều phối gom toàn bộ Issues lại để theo dõi tiến độ Bảng trắng Kanban treo tường gom các tờ giấy note

3 Chế độ hiển thị quyền lực

  • Board (Kanban): Kéo thả trực quan giữa các cột: Todo ➡️ In Progress ➡️ Done.
  • Table: Bảng tính dạng Notion/Excel hiển thị người phụ trách, độ ưu tiên (Priority), ngày đến hạn.
  • Roadmap: Biểu đồ Gantt trực quan thời gian triển khai của từng tính năng lớn (Epic).

GitHub Projects is an adaptable, flexible tool for planning and tracking work on GitHub, functioning like native Jira, Trello, or Linear.

Project Views

Toggle between Kanban Board, Spreadsheet Table, and Gantt Roadmap views to organize issues across multiple repositories seamlessly.

Quy Trình Pull Request (PR) & Code Review

Khi làm việc trong các công ty công nghệ hoặc đóng góp mã nguồn mở, bạn không bao giờ được tự ý push thẳng vào main. Quy trình chuẩn mực luôn tuân theo 4 bước:

  1. Bước 1: Tạo nhánh tính năng trên máy tính và push nhánh đó lên GitHub: git push origin feature/login.
  2. Bước 2: Vào GitHub bấm nút xanh "Compare & pull request".
  3. Bước 3: Viết mô tả chi tiết: Bạn đã thay đổi gì, tại sao thay đổi, và đính kèm ảnh chụp màn hình minh họa. Gắn thẻ trưởng nhóm (Tech Lead) vào ô Reviewers.
  4. Bước 4: Trưởng nhóm kiểm tra từng dòng code (Diff). Nếu hoàn hảo, họ sẽ bấm Approve và Merge pull request để hoàn tất!

Pull Requests (PRs) let you tell others about changes you've pushed to a branch in a repository on GitHub. Once a PR is opened, you can discuss and review the potential changes with collaborators and add follow-up commits before your changes are merged into the base branch.

Tự Động Hóa CI/CD Với GitHub Actions

GitHub Actions cho phép bạn thiết lập các kịch bản chạy tự động trên máy chủ ảo của GitHub mỗi khi bạn git push hoặc mở Pull Request. Ví dụ:

  • Tự động kiểm tra lỗi cú pháp và chạy bài test (Unit Test).
  • Tự động đóng gói phần mềm và tạo file cài đặt .exe trên trang GitHub Releases.
  • Tự động build website và đẩy lên GitHub Pages.

Mỗi kịch bản được lưu dưới dạng file YAML nằm trong thư mục .github/workflows/:

name: CI Pipeline
on: [push]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm install
      - run: npm test

GitHub Actions is a continuous integration and continuous delivery (CI/CD) platform that allows you to automate your build, test, and deployment pipeline. You can create workflows that build and test every pull request to your repository, or deploy merged pull requests to production.

Bảo Mật Token (PAT), SSH & Phím Tắt Ma Thuật

1. Personal Access Token (PAT)

Từ năm 2021, GitHub đã chấm dứt hoàn toàn việc dùng mật khẩu tài khoản để push code qua HTTPS. Thay vào đó, bạn phải sử dụng Personal Access Token (PAT) có tiền tố ghp_... làm mật khẩu xác thực.

Bảo vệ Token: Tuyệt đối không bao giờ commit token vào file code công khai! GitHub có robot quét tự động và sẽ ngay lập tức vô hiệu hóa token nếu phát hiện bị lộ trên internet.

2. Phím tắt ma thuật trên trình duyệt web GitHub

Khi đang xem bất kỳ repository nào trên trình duyệt, hãy thử các phím tắt siêu tốc này:

Phím bấm Tác dụng ma thuật
. (Dấu chấm) Mở ngay trình soạn thảo Visual Studio Code trực tuyến (github.dev) ngay trong tab trình duyệt!
t Bật thanh tìm kiếm file thần tốc (Quick File Finder), gõ tên file là nhảy đến ngay.
b Xem Git Blame để biết ai đã viết từng dòng code vào ngày tháng nào.
y Tạo liên kết cố định (Permalink) của dòng code để chia sẻ cho đồng nghiệp.

3. Tối ưu tốc độ gõ lệnh với Git Aliases

Bạn có thể kích hoạt bộ phím tắt rút gọn (git s thay cho git status, git c thay cho git commit) bằng script đính kèm:

# Dành cho Windows PowerShell:
./scripts/git-setup-aliases.ps1

# Dành cho macOS / Linux Terminal:
chmod +x ./scripts/git-setup-aliases.sh && ./scripts/git-setup-aliases.sh

1. Personal Access Tokens (PAT)

GitHub requires personal access tokens (beginning with ghp_) or SSH keys for git over HTTPS authentication. Never expose your token in public repositories.

2. GitHub Web Shortcuts

Press . (period) to open the full web-based VS Code environment instantly on any repository. Press t to open file finder.

Cỗ Máy Thời Gian: Kỹ Thuật Lùi Về Bất Kỳ Phiên Bản Nào

Một trong những nỗi sợ lớn nhất của người mới học lập trình là: "Lỡ tôi viết code sai làm hỏng cả dự án, hoặc lỡ bấm nhầm xóa mất code thì có lấy lại được bản hôm qua không?"

Câu trả lời khẳng định 100%: CÓ! Đó chính là lý do tối thượng mà Git ra đời. Một khi bạn đã commit, Git đóng vai trò như một "cỗ máy thời gian" ghi lại từng tọa độ lịch sử. Bạn có thể quay về bất kỳ thời khắc nào trong quá khứ chỉ bằng 1 câu lệnh!

1. Kịch bản 1: "Tôi chỉ muốn xem lại quá khứ, không làm xáo trộn hiện tại"

Bạn muốn đưa toàn bộ thư mục trên máy tính quay ngược về trạng thái của một commit cũ để kiểm tra, chạy thử hoặc đọc lại logic cũ:

# Lấy mã SHA (ví dụ: a1b2c3d) bằng lệnh git log --oneline
git checkout a1b2c3d

# Hoặc dùng cú pháp Git đời mới:
git switch --detach a1b2c3d
Hiện tượng "Detached HEAD" (Đầu rời là gì?): Lúc này con trỏ HEAD đang bay lơ lửng trên cỗ máy thời gian để soi lại quá khứ mà không gắn vào nhánh nào. Toàn bộ file trong VS Code của bạn sẽ lập tức biến hình thành phiên bản cũ ngày đó.
• Muốn trở về thực tại ngay lập tức: git switch main
• Muốn phát triển tiếp một nhánh mới từ mốc quá khứ này: git checkout -b nhanh-moi-tu-qua-khu

2. Kịch bản 2: Hoàn tác an toàn khi làm việc nhóm (git revert)

Tính năng vừa tạo bị lỗi và đã lỡ git push lên GitHub. Để không làm gãy lịch sử của các đồng nghiệp khác, tuyệt đối không xóa commit, hãy dùng git revert:

git revert a1b2c3d

Cơ chế ma thuật: Git sẽ tự động tạo ra một commit mới có nội dung đảo ngược hoàn toàn những gì commit a1b2c3d đã làm. Lịch sử code vẫn thẳng hàng, an toàn và minh bạch tuyệt đối!

3. Kịch bản 3: Hủy bỏ commit khi làm việc cá nhân (git reset)

Khi bạn chỉ đang code một mình trên máy cá nhân và muốn "xóa sổ" các commit vừa tạo để làm lại từ đầu:

Lệnh Reset Tác động đến Code Khi nào nên dùng?
git reset --soft HEAD~1 Hủy commit, nhưng giữ nguyên toàn bộ code trong Staging Area Khi muốn sửa lại lời nhắn commit hoặc gom thêm file vào commit trước
git reset --mixed HEAD~1 Hủy commit, đưa code về trạng thái chưa Stage (mặc định) Khi muốn lọc lại từng file để commit riêng rẽ
git reset --hard HEAD~1 Xóa sạch toàn bộ code sửa đổi, quay về y hệt phiên bản trước Khi bạn viết thử nghiệm hỏng bét và muốn vứt bỏ hoàn toàn code lỗi

4. Phao cứu sinh tối thượng: Hộp đen "git reflog"

Nếu bạn lỡ tay chạy git reset --hard làm mất cả những commit quan trọng thì sao? Đừng hoảng loạn! Git có một chiếc hộp đen máy bay lưu lại mọi bước chân:

# Xem lại toàn bộ lịch sử di chuyển của HEAD trong 30-90 ngày qua
git reflog

# Kết quả mẫu:
# 7b8c9d0 HEAD@{0}: reset: moving to HEAD~1
# a1b2c3d HEAD@{1}: commit: feat: chuc nang cuc ky quan trong (đã lỡ bị xóa!)

# Hồi sinh commit bị xóa nhầm trong 1 giây:
git reset --hard HEAD@{1}

5. Lùi về phiên bản cũ trực tiếp trên giao diện web GitHub

Không cần gõ bất kỳ dòng lệnh nào, bạn vẫn có thể tải lại bản code ngày xưa ngay trên trình duyệt:

  1. Vào trang chủ Repository trên GitHub, bấm vào dòng chữ Commits.
  2. Tìm đến phiên bản trong quá khứ bạn muốn lấy lại.
  3. Bấm vào biểu tượng dấu < > (Browse repository at this point in the history) ở góc phải commit.
  4. GitHub sẽ hiển thị toàn bộ kho code y như ngày tháng đó! Bấm nút xanh Code ➔ Download ZIP để tải trọn gói về máy tính.

One of the greatest superpowers of Git is its ability to act as a Time Machine. Once committed, your code snapshots are preserved permanently.

1. Inspecting the Past (Detached HEAD)

git checkout a1b2c3d
# Or modern Git:
git switch --detach a1b2c3d
# Return to current:
git switch main

2. Safe Rollback for Teams (git revert)

Creates an inverse commit without rewriting previous history:

git revert a1b2c3d

3. Local History Rewind (git reset)

Use --soft, --mixed, or --hard depending on whether you want to preserve staged files or completely discard local changes.

4. The Ultimate Lifesaver: git reflog

Recovers accidentally deleted commits and branches from Git's internal safety ledger.

5. Browsing Old Commits on GitHub Web

Visit repository commits history, click the < > icon next to any past commit, and download the full ZIP snapshot directly.
